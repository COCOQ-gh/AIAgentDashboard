現在のセッションの消費トークンを確認し、作業の進め方を調整する。追加オプション: $ARGUMENTS

1. `node src/cli.mjs $ARGUMENTS` を実行する(既定で `$CLAUDE_CODE_SESSION_ID` のセッション。無ければ cwd の最新セッション。`--list` で一覧、`--session <id>` で指定)。
2. 出力の「現在のコンテキスト」「提案」「消費の多い指示」「ツール別の文脈追加」を読み、次の方針に当てはめる:
   - コンテキストが窓の 70% 超 → 区切りの良いところで /compact、または残りを別セッションへ。
   - キャッシュ読取が大半 → 同じ文脈を往復ごとに再送している。独立した読み取り・コマンドは 1 回の応答にまとめ、探索はサブエージェントに委任する(サイドチェーンは親の文脈を増やさない)。
   - 文脈を増やしたツールが Read / Bash → 大きなファイルは offset/limit で範囲指定、コマンド出力は head・grep で絞る、同じ内容を二度読まない。
   - 1 つの指示に API 呼出が集中 → 計画してから一括で実行する。
3. ユーザーへは 3 行以内で報告する: 合計と現在のコンテキスト量、最大の消費要因、これからの作業で変えること。レポート全文は貼らない。
